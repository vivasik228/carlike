# CarLike — автосервис, детейлинг и тюнинг в Казани

Реализованный Next.js-сайт: главная со всеми секциями, 3 направления, 12 услуг, демонстрационная галерея и страницы проектов, контакты, юридические документы и серверный прием заявок. Фотографии реальные; ИИ-изображения исключены. Данные бизнеса, цены и фотографии редактируются отдельно от компонентов.

Публичная демонстрация: [vivasik228.github.io/carlike](https://vivasik228.github.io/carlike/). Исходники: [vivasik228/carlike](https://github.com/vivasik228/carlike).

На GitHub Pages размещается демонстрация интерфейса без формы сбора данных. Полное приложение с серверным приёмом заявок остаётся в ветке main. Как устроена публикация и повторная сборка — [docs/PUBLICATION.md](docs/PUBLICATION.md).

## Запуск

Требуется Node.js 24+ (используется встроенный node:sqlite) и pnpm. Установленные зависимости и lockfile включены в рабочую папку, в архив исходников node_modules не включается.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Откройте http://127.0.0.1:3000. Без настроенного хранилища форма честно сообщает о недоступности онлайн-заявок; звонок и маршрут работают. Никакие заявки не отправляются в сторонние сервисы.

Проверки:

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm build
```

При корпоративных корневых сертификатах Node 24 поддерживает `NODE_USE_SYSTEM_CA=1`; проверку TLS отключать не нужно.

## Форма и хранилище

Скопируйте `.env.example` в `.env.local`. Production-приём включается только при заданных ключе, пути БД, HTTPS-домене, `STORAGE_REGION=RU`, `TRUST_PROXY=true`, `LEGAL_APPROVED=true` и заполненных фактических реквизитах. Сама настройка RU не доказывает местоположение оборудования: это проверяет оператор у хостера.

Ключ создаётся локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Сохраните его в `LEAD_ENCRYPTION_KEY` и защищённом резервном хранилище. Не меняйте ключ у существующей БД без миграции: старые данные станут нечитаемыми.

Для локальной проверки только с синтетическими данными:

```env
ENABLE_DEV_STORAGE=true
LEADS_DB_PATH=./runtime/leads.sqlite
LEAD_ENCRYPTION_KEY=<ваш-32-байтный-ключ-в-base64>
```

Режим действует только вне production. На локальной машине не следует собирать реальные клиентские данные до проверки инфраструктуры.

`POST /api/booking` проверяет Origin, JSON, размер до 8192 байт, поля Zod, отдельное согласие, hash актуального документа и honeypot. В SQLite первично сохраняются зашифрованная AES-256-GCM заявка и доказательство согласия: время, редакция, полный текст и SHA-256. Транзакция завершается до ответа об успехе. Один requestId с теми же данными возвращает прежний ID, с изменёнными — 409. Ограничения: 30 попыток в минуту и 5 заявок за 10 минут на источник. В production источник определяется по X-Real-IP доверенного proxy.

Юридические страницы динамические. `GET /api/consent` возвращает текущие hash и редакцию; устаревшие формы не принимаются. Клиенту не передаются секреты шифрования, пути БД или CRM-токены.

## Работа с заявками

Серверный CLI читает `.env.local` / `.env`; запускать только уполномоченным лицам на сервере. Список содержит ID и время, без содержимого заявки.

```sh
pnpm leads list
pnpm leads export CL-<uuid> /закрытая-папка/заявка.json
pnpm leads delete CL-<uuid>
```

Экспорт содержит персональные данные, файл создаётся с правами 0600 и не перезаписывается. Утвердите регламент доступа, хранения и удаления. Функции автоматического удаления по сроку пока не включены: фактический срок должен установить оператор. После удаления учитывайте резервные копии по своему регламенту.

## CRM

`src/lib/crm.ts` содержит интерфейс адаптера и webhook-уведомитель. В основной БД создаётся outbox; worker / планировщик на вашем российском сервере вызывает `pnpm leads notify`. Для включения нужны `CRM_NOTIFY_ENDPOINT` (HTTPS), `CRM_NOTIFY_TOKEN` и `CRM_REGION=RU`. Передаётся только `{leadId}`, без имени, телефона и комментария. При ошибке доставки запись остаётся для повторной попытки; принимающая CRM должна поддерживать дедупликацию по leadId.

Перед полноценной передачей персональных данных в российскую CRM проверьте договор, размещение данных, основания обработки и обновите документы. Замените `LeadStore` на PostgreSQL-репозиторий при переходе к нескольким экземплярам приложения; текущая SQLite-реализация предназначена для одного постоянного сервера.

## SEO и аналитика

Перед production-сборкой задайте настоящий `NEXT_PUBLIC_SITE_URL`. Он используется для canonical, Open Graph, sitemap и robots. Без домена preview помечен noindex, robots запрещает индексацию, sitemap пустой. Предусмотрены уникальные метаданные услуг, семантические заголовки, хлебные крошки и JSON-LD AutoRepair / LocalBusiness без неподтверждённых сведений.

`NEXT_PUBLIC_YANDEX_VERIFICATION` — код Вебмастера; региональность Казань и связь с Яндекс Бизнесом настраиваются в соответствующих кабинетах. `NEXT_PUBLIC_METRIKA_ID` — счётчик Метрики; загружается только после разрешения аналитики, без Вебвизора. События: `click_phone`, `click_route`, `open_booking`, `submit_booking_success`, `click_service`. Содержимое формы в события не передаётся. Выбор можно изменить в подвале и на странице cookie.

Карта по умолчанию открывает официальную карточку. Для встраивания используйте подтверждённый URL `https://yandex.ru/map-widget/...` из кода карты в `NEXT_PUBLIC_MAP_EMBED_URL`; iframe загружается только по кнопке.

## Развёртывание в РФ

До коммерческого запуска выполните `docs/LAUNCH-RU.md` и юридическую проверку. Нельзя автоматически размещать сбор персональных данных на иностранном hosting/edge. Публичная демонстрация интерфейса размещена отдельно; серверный приём заявок и российский хостинг пока не настроены.

Для обычного Node-сервера: `pnpm build`, затем `pnpm start` за HTTPS reverse proxy. Скрипт start копирует assets в `.next/standalone` и запускает standalone-сервер на 127.0.0.1:3000; HOSTNAME и PORT можно изменить через окружение. Dockerfile выполняет копирование автоматически и слушает интерфейс контейнера.

Docker:

```sh
docker build --build-arg NEXT_PUBLIC_SITE_URL=https://<ваш-домен> -t carlike .
docker run --env-file .env.production \
  -p 127.0.0.1:3000:3000 \
  --mount type=bind,source=/var/lib/carlike,target=/var/lib/carlike \
  carlike
```

Создайте каталог `/var/lib/carlike` с владельцем UID 1000 и правами 0700; БД и WAL не должны быть web-доступны. TLS, доверенный proxy, лимит body, резервные копии и firewall настраиваются на сервере. Не используйте ephemeral-файловую систему/serverless для этой SQLite-конфигурации. Ограничьте хранение access-логов и исключите тела запросов из логирования.

Значения `NEXT_PUBLIC_*` встраиваются при сборке: после их изменения нужна новая сборка. Юридические реквизиты берутся в runtime; после смены редакции/процессов обновите `legal.version` и сервер.

## Барабан услуг на первом экране

Девять услуг редактируются в `src/config/hero-services.ts`: id, title, description, image и href. Пустое image сохраняет основную реальную фотографию; локальный путь к подтверждённому фото включает crossfade после загрузки. Компонент `ServiceRoller` и хук `useServiceRoller` используют GSAP 3.13, три копии списка и бесшовную нормализацию позиции.

Управление: колесо только над барабаном, кнопки, стрелки при фокусе, Enter для открытия услуги, короткие вертикальные свайпы. Остальная страница прокручивается обычно. Reduced motion отключает переходы. Обработчики, ResizeObserver, таймлайн и резервный таймер завершения очищаются при размонтировании.

## Ограничения проверки

Состояния интерфейса: форма загружает актуальное согласие, показывает ошибку с повтором, сохраняет поля и ограничивает ожидание 12 секундами. Конфликт повторного обращения и смена согласия имеют разные способы восстановления. Галерея поддерживает пустой каталог и пустой фильтр, фотографии показывают загрузку/ошибку/повтор. Детали доработки по карточкам — `docs/ui-cards-plan.md`, результаты проверки — `docs/VERIFICATION.md`.

Фактическое размещение в РФ, внешний TLS, CRM, Яндекс-счётчик, юридические реквизиты и реальная доставка обращения сотруднику требуют настройки владельцем. Код и локальный сайт можно проверить без этих интеграций. Core Web Vitals в реальном трафике не измерялись; фото локальны, сжатые, lazy-loaded кроме первого экрана, шрифты локальные, учитывается reduced motion.
